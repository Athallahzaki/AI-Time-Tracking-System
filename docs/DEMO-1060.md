# Demo di laptop GTX 1060 (1 kamera, MediaMTX, rekognisi wajah)

Profil: `engine/config/demo-1060.yaml`. Dasar angkanya `batch_check` 4 Okt di
laptop Razer GTX 1060 Max-Q, video `uji-video2.mp4` (848x478, yuv420p):

| model | eager | cuda_graph | hasil |
|---|---|---|---|
| D-FINE M | 70-75 ms | 70,9 ms | identik, graph tidak membantu |
| D-FINE S | 55-59 ms | **48,1 ms** (1,17x) | identik |

Keputusan: S, FP32 (`half: false`, wajib di Pascal), `cuda_graph: true`,
`target_fps: 8`, rekognisi async. `fast_preprocess` tidak berlaku karena
video lebih kecil dari 640 di salah satu sisi.

Berbeda dari RTX 4060: di 1060 GPU-nya sendiri yang lambat, sehingga
menghapus biaya peluncuran kernel (CUDA graph) hampir tidak terasa di M.

**Angka ini berlaku untuk video 848x478.** Begitu akses CCTV ada, cek resolusi
main stream (`ffprobe ... rtsp://...`), lalu ulangi `batch_check` dan gladi
bila berbeda.

## 0. Sekali saja

```powershell
python scripts/check_gpu_env.py         # libreyolo 1.6, torch +cu126, onnxruntime-gpu < 1.27
python -m pytest engine/tests -q
```

Baris `onnx-sesi` harus muncul di `check_gpu_env`. Bila tidak muncul, berarti
`models/scrfd_10g_bnkps.onnx` tidak ditemukan dari folder repo, dan rekognisi
tidak akan jalan.

## 1. Preflight

```powershell

.\scripts\publish_test_video.ps1 -Video <video-demo>.mp4 -Fps 25          # terminal 2
python scripts/preflight_demo.py                                          # terminal 3
```

Yang dicek preflight:

- sisa penanda konflik git di config;

- dua model wajah ada (dan bukan pointer LFS);
- roster;
- LibreYOLO cukup baru untuk cuda_graph;
- MediaMTX cam01 READY;
- port 8765/8000/5173 bebas;
- git bersih.

Semua GAGAL wajib beres. PERINGATAN boleh untuk gladi, tetapi tidak untuk demo.

## 2. Gladi A: engine saja + probe (10-15 menit)

Backend jangan dijalankan, karena engine hanya melayani satu backend.

```powershell
python -m engine.runtime --config engine/config/demo-1060.yaml --tcp 127.0.0.1:8765 `
    --health-seconds 2 --outbox engine/data/outbox-gladi.sqlite3
python scripts/lag_probe.py --camera cam01=rtsp://127.0.0.1:8554/cam01 --minutes 15 --out bench-out/gladi-1060.csv
```

Engine butuh ±1 menit untuk memuat model dan warmup sebelum frame pertama. Lulus bila:

- fps median ±8 dan stabil (tidak ada turun ke 5-6 yang bertahan);
- umur kotak median < 0,5 dtk, tanpa tren naik;
- log worker rekognisi menunjukkan wajah **diproses**. Di 848x478 ini pertanyaan
  terbesar. Bila hampir nol, wajah di video terlalu kecil (< `min_face_px` 40):
  rekam video demo dengan orang yang lewat dekat kamera, atau pakai cadangan
  fake engine untuk alur pelanggaran (workplan demo §7).

## 3. Gladi B: alur lengkap


## Tombol mundur saat gladi

| Gejala | Ubah di demo-1060.yaml |
|---|---|
| Error / kotak aneh setelah warmup | `detector.cuda_graph: false` (hilang ±7 ms) |
| fps tetap < 7 | `core.target_fps: 6` (lebih baik stabil) |
| Sisa waktu lega di gladi A | `core.target_fps: 10` |
| Identitas hilang / aneh | `recognition.execution: "sync"` |
| Wajah tidak pernah terdeteksi | bukan config: video/kamera terlalu jauh |

Laptop dicolok charger, mode performa, cooling pad bila ada. CPU laptop ini
throttle ke 1,5-2,5 GHz dan membuat hasil berubah ±50-100% antar-run.
